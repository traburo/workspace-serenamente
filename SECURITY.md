# Política de seguridad

## Cómo informar una vulnerabilidad

No publiques vulnerabilidades, credenciales, datos personales ni capturas sensibles en Issues. Utiliza el reporte privado de vulnerabilidades de GitHub cuando esté habilitado. Si ese canal no está disponible, contacta directamente a la persona propietaria del repositorio por un canal previamente acordado.

Incluye únicamente la información necesaria para reproducir el problema: componente afectado, impacto, pasos de reproducción y una propuesta de mitigación si existe. No incluyas datos reales de participantes.

## Alcance prioritario

- Aplicación 07_Sistema_Comercial/CONOCEME_MVP.
- Panel administrativo, sesiones y exportaciones.
- Base de datos y migraciones.
- Correos, recordatorios y credenciales de proveedores.
- Fotografías, datos de contacto y cualquier información de participantes menores de edad.

## Compromiso de respuesta

La recepción se confirmará dentro de 5 días hábiles. La severidad y el plan de corrección se comunicarán después de validar el hallazgo. Los problemas críticos que expongan credenciales o datos personales deben contenerse antes de cualquier publicación detallada.

## Versiones mantenidas

Solo la rama main y el entorno de prueba vigente reciben correcciones de seguridad. Los prototipos y materiales archivados no deben considerarse sistemas mantenidos ni desplegarse sin una nueva revisión.
